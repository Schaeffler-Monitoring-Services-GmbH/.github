# Contributing

Thanks for your interest in contributing.

## Workflow

1. Open (or find) an issue describing the change before starting larger work.
2. Fork or branch from the repository's default branch.
3. Keep changes focused and the diff small.
4. Commit using [Conventional Commits](https://www.conventionalcommits.org/)
   (`feat:`, `fix:`, `docs:`, `chore:`, …).
5. Open a pull request and fill in the template.

## Requirements

- Do not commit secrets or credentials. Use environment variables and a
  checked-in `.env.example` where configuration is needed.
- Match the existing code style and formatting of the repository.
- Add or update tests for behaviour changes.
- Ensure CI is green before requesting review.

## Review

- At least one maintainer review is required before merge.
- Squash-merge is the default, keeping the history linear.

## Conduct

Be respectful and constructive. See `CODE_OF_CONDUCT.md` if present.
